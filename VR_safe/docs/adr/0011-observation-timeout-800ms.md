# 观察超时救急放宽到 800 ms

现场 CPU MediaPipe 基准约 5.08 Hz（帧间隔中位数 0.201 s），原来 300 ms 的观察超时只有 1.5 倍余量；viewer 的 JPEG 编码和偶发慢帧会把间隔推到 0.35 s，导致 supervisor 频繁以“观察超时”锁存，RJ 确认时又因当前状态 UNKNOWN 被拒。现场决定先把 `observation_timeout_s` 从 0.3 s 放宽到 0.8 s，让操作员能连续操作。

## Consequences

- 相机/感知故障的 HOLD 延迟从 0.3 s 增加到 0.8 s；臂/底盘的本地 target/许可看门狗仍是 200/300 ms，不依赖这个值。
- 这是救急值，不是最终安全指标。感知优化到 ≥10 Hz、p95 帧间隔 <0.2 s 后，应把超时收紧回 0.3 s。
- 同时给 `OCCUPIED` 加 2 帧去抖，减少远处低置信度点的单帧误停。
